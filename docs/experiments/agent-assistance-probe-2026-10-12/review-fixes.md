# Preparation corrections before paid dispatch

Codex's review of `06bdf1d` raised two valid P1 findings. The existing Service
normally reacquires mutable issue/default-branch data, and the ordinary handoff
includes generated bridge files and does not itself provide this study's 16 KB
excerpt packet. The original preparation did not yet make those two execution
details reproducible. No source search or paid call has run.

`FrozenAssistanceService` now supplies only the retained normalized discussion and
target sample to the existing Service preparation method. Construction verifies
the canonical frozen-input fingerprint, public repository/issue identity and
protocol target revision. Normal Provider interpretation still runs, once, on
that frozen discussion. Target inquiry delegates to the existing explicit pinned
revision/file-SHA checks. Donor search, transport, account verification, budgets,
store, stop behavior and matching remain the ordinary implementation. This is
an experiment-local input adapter, not a product mode or alternate runner.

The frozen target is acquired from the unmodified pinned native Git clone using
its immutable tree and blob objects, processed by the existing PublicGitHub
normalization/sampling. Its public repository and commit metadata were confirmed
with read-only GitHub connector reads. Git blob content hashes and the commit's
tree hash are verified. The manifest identifies files, catalogue and acquisition.
It contains one initial manifest file and the ordinary 195-entry file catalogue;
the one model-selected inquiry may read up to three of those pinned files.
No source mechanism is supplied by the operator.

The original selection retained all six comments but no issue timeline. That
absence now explicitly blocks a claim of complete discussion context: normalized
`context_complete` is false, with the missing timeline documented. We do not
silently reconstruct an empty timeline as evidence of completeness or incorporate
later discussion into the frozen demand. Unknown context may legitimately cause
deferral; it does not justify adding requirements.

`assistance_packet` deterministically projects the existing validated handoff.
It retains source identity/revision, capability and compatibility hypothesis,
existing contribution, assumptions, limits and exact cited source excerpts from
the acquired snapshot. It records omitted handoff fields and duplicate/non-source
references. Generated target bridge files/steps and request discussion are omitted;
both arms already receive the original full demand. Source spans are never clipped.
Invalid/missing spans, redaction needs or a serialized UTF-8 packet over 16000
bytes stop the cohort without replacement or another call.

Four additional offline regressions exercise actual Service preparation against
forbidden mutable reads, changed frozen input rejection, deterministic bridge-free
projection with exact source text, and invalid/oversized evidence rejection.
Together with the original four contract tests, eight tests pass. Existing frozen
selection, acceptance, prompts, bounds and preparation results are unchanged.

The common direct attempt is now frozen in `common-patch.json` and
`common-report.md`. Independent parent checks pass the public reproduction and
48 native monkeypatch tests; the fixed assessor cases remain 6 passed / 2 failed
(passthrough and mixed custom setters). This is a bounded unresolved continuation
need, not a failure of the original issue's direct repair. The feedback supplied
to later arms must preserve this distinction.
