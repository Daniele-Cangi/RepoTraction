# End-to-end Discover cohort: results

**Negative result: zero demonstrated advantageous autonomous reuse opportunities
from fifteen selected discussions across three sources.** All three jobs ran
successfully, but neither of the two executable hypotheses produced a surviving
source binding. There are zero assisted connections and zero target integrations.
Successful transport, valid output and correct rejection are not discovery wins.

## The two executable hypotheses

**Black / Ouroboros: PEP 440 membership.** A constraint-membership predicate is
a defensible part of the requested updater correction. It does not establish
receipt selection, marker handling, preflight ordering, recovery or installed
version verification. The source-blind baseline strategy is direct use of the
existing third-party `packaging` specifier implementation, already named as a dependency in
the retained demand context. A Black helper that reads a version requirement is
not thereby a constraint-membership implementation.

The existing extractor yielded 29 callable slices, of which 15 accepted the
contract's positional arity. None satisfied the original contract or the cohort
with four independent checks. There were 162 omission records, chiefly package
dependencies and computed state; these are limitations of this bounded slice
search, not proof that the entire Black repository cannot help. No runtime load
errors or omitted observation records occurred in the actual searches.

**Scrapy / Yorishiro: preserve a raw HTTP target.** The independent reviewer
supports preservation as a narrow invariant, but the proposed two-argument
contract can be satisfied simply by returning the second argument. That says
nothing about actual flow storage, URL conversion or HTTP resend. The discussion
already describes a local correction and a remaining adoption question. It also
contains Go runtime evidence overlooked by the proposal's `runtime=unknown`;
the later compatibility analysis identifies the Python/Go mismatch.

The existing extractor yielded 19 callable slices and ten arity-eligible
bindings, with 26 dependency/state omission records. None satisfied either
cohort. Even a finite pass would not demonstrate lifecycle behavior, runtime
adoption or improvement over the described local design. The original contract
and runtime field were preserved, not repaired after review.

Four existing WASI executions completed in **10.430 seconds**, with no host
execution of external source. Original and independent observations are stored
separately in [behavioral-observations.json](behavioral-observations.json).
Independent cohorts retain original examples and replace the checks with four
new inputs per contract; their case provenance is explicitly attributed. The
50 binding observations comprise the same 25 bindings tested twice, not 50
independent opportunities.

No source binding survived, so bridge export/execution, measured direct-baseline
comparison, adoption/license review of a surviving bridge and performance
advantage measurement were **not reached**. No substitute bridge was manufactured
to complete those boxes. Baseline strategies were frozen before source behavior
inspection; they are not claimed as executed implementations or measured wins.

Post-run export, independent AI review, sandbox checks and outcome recording
took **859.382 seconds of wall time** through the outcome record. This is not
active human labor or isolated reviewer inference time; no human adjudication
was performed. Subsequent report editing and CI are outside that interval.

## What this establishes, and the decision it supports

**Evidence:** the ordinary pipeline can complete the cohort, preserve its
evidence and reject misleading similarities. It did not find a demonstrably
advantageous new use. Examples include Jinja sync/async selection versus a Rust
dispatch refactor, Python line formatting versus gettext/prose wrapping, and
Scrapy client request construction versus a Haskell server surface. These are
operation and adoption gaps, not transport failures.

The actual automatic queries remained broad: Jinja used `template filter context
injection` and `sync async dispatch`; Black used `python line wrapping` and
`python target version parser`; Scrapy used `http request object initialization`
and `json http request serialization`. They found related discussion contexts,
but the resulting candidates did not establish the same reusable computation
and a beneficial adoption route. Exact queries and selection order are retained
in the job results.

**Inference, not a causal experiment:** broad source-derived terms and a
pure-function example interface appear poorly aligned with several retrieved
integration/refactoring demands. This cohort does not isolate whether acquisition,
source sampling, query generation, ranking, representation or source choice is
the dominant cause. It does not establish an overall success rate, absence of
useful connections in these repositories, or that broader execution would help.
The source-blind review supports conservative abstention here; forcing more
contracts would not supply missing adoption value.

**Recommendation:** close this cohort as a negative end-to-end demonstration.
Do not open an infrastructure, retrieval-weight, citation or contract-polishing
PR in response, and do not spend the remaining allowance. Before authorizing
another run, decide whether to change the functional discovery strategy itself:
the evidence sought must be an operation a real target needs, an existing source
that actually performs it, and a concrete reason to reuse it rather than the
simpler available solution. This report does not implement that change or infer
that another architecture is required. The infrastructure phase remains closed.

The source-blind reviewer receives only the review packet, excluding candidate
source identities/code, query terms and compatibility results. Original
discussion text is not censored: incidental software names can still appear.
This is an independent AI review in a separate context, not a human oracle or
fully blind population study. No new acquisition is permitted to rescue cases.

The ordinary service prepares hypotheses and unexecuted artifacts; it does not
perform the later independent adjudication or automatically qualify the
behavioral prototype. The authorized post-run checks are explicitly separate
evaluation work using existing WASI functions. They do not establish autonomous
target integration. Unknown benefit, incomplete target context and unresolved
runtime remain unknown; finite example passes cannot override those gaps.
