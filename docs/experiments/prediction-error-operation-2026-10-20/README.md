# Excluded-prediction errors: operation defined, pertinent code not reached

The unchanged Discover GitHub reader did **not** reach an implementation of the
operation identified by the G20 diagnosis in this bounded, assisted search.
Three fixed queries returned 60 distinct metadata entries. Only one satisfied the
predeclared metadata selection rule: `rvalavi/blockCV`, at rank 9 for the second
query. Its default sample contains documentation, not executable source. This is
a retrieval outcome, not evidence that the operation has no external solution.

Only RepoTraction was changed. There were no Satellite writes, experiments,
messages, PR updates or merges, and no paid AI calls. Historical evidence is
unchanged. This work does not recommend installing a package or implementing a
new reader, runner, scoring system or infrastructure.

## The operation and the strongest direct alternative

The input diagnosis is the already exposed conditional G20 correction failure,
preserved at Satellite revision
[`b546e27`](https://github.com/Daniele-Cangi/Satellite-RF-Observatory/blob/b546e271e05fa0a885bb4091a01286ce8096baa3/research/exploratory/g20-diagnosis-2026-10-20/README.md).
It contrasts training post-fit residuals with errors of predictions for excluded
observations. It does not prove that changing that learning target will improve
RF performance, that every failure needs software rather than physical information,
or that the target represents a typical Missing Link use case.

The missing operation is to **construct prediction errors after jointly excluding
the observations being predicted from all fitting and learned preprocessing**,
with explicit unsupported outcomes when the remaining data cannot estimate the
requested functional. Temporal and continuity boundaries must be respected.
Masking a latent filter coordinate after fitting calibration to that response
does not satisfy this contract. Random train/test splitting alone does not either.

This is a missing step in the tested correction method, not an absent primitive
in Satellite. Its existing `network_clocks.fit`,
`phase_continuity.withheld_segment` and `source_geometry.source_link_prediction`
already support an explicit-refit direct alternative. An external contribution
would need a concrete advantage over that alternative: for example equivalent
excluded-prediction errors without repeated full fits, with weighting,
rank/estimability and fixed-model assumptions stated. Native benefit remains
untested. No new RF model or implementation was made here.

For the separate G31 example, removing all reference-clock observations leaves
an unrestricted epoch clock unobserved. Neither a cross-validation utility nor
an algebraic shortcut restores that information. A finite prediction obtained
by adding a prior would change the assumptions, not complete the same operation.

`NEWS.md`: 62,657 accepted bytes. All other file types were ineligible, including
the R implementation. The eligible catalogue therefore supplies no additional
source path for the permitted targeted reads. The reader reports incomplete
coverage; this is not a package defect or proof its implementation is absent.
Executable exclusion behavior, weighted inverse-model equivalence, estimability
handling, integration effort and benefit relative to refitting all remain
**unknown**. Documentation-only relevance is not counted as a useful connection.

## Decision

The diagnosis gives Missing Link a more precise operation and direct alternative,
but this fixed retrieval does not supply executable evidence for an external
advantage. Do not repeat a generic missing-data transfer, tune RF corrections,
or expand infrastructure on the strength of this result. Whether useful code
is hidden behind the unselected sparse metadata remains unresolved. Reading
that evidence would be a separate exploratory follow-up, not a positive result
of this fixed comparison. No such follow-up or paid cohort is started here.
