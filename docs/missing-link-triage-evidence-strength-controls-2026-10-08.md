# Offline controls for evidence strength

The [6 October source comparison](missing-link-triage-prospective-result-2026-10-06.md)
exposed two grounding problems: declared delegate behavior was treated as
demonstrated behavior, and a possible conditional difference as an established
counterexample. Eighteen authored controls added on October 8 separate these
cases without changing the model prompt, schema, normalizer or production gates.

## Declared contracts and demonstrated behavior

The [synthetic fixtures](../tests/test_missing_link_triage_evidence_strength_controls.py)
keep a documented wrapper identical while supplying different inert callbacks.
A constructor can return empty text, nonempty text or an object; a chunk producer
can return lists or tuples. Only the wrapper is cited in the comparison context.
The callbacks used as executable witnesses are not supplied implementation
evidence, and none is code acquired from another repository.

An explicitly declared-contract comparison remains permissible. A claim about
actual constructor contents or produced chunk types requires more than repeating
the wrapper's docstring. Unknown output is retained without converting missing
list proof into proof of tuple output. Separately visible None dispatch remains
supported even when the dispatched constructor's result is unknown.

## Conditional possibilities and counterexamples

A conditional formatting wrapper can preserve commas or replace them, depending
on an unseen helper's result. Merely finding that conditional path establishes
neither unconditional alignment nor an actual differing result. These controls
contrast that gap with a literal semicolon replacement for the explicit input
`1,234`, which supports a bounded output difference. Even literal replacement
does not mean every input changes: `1234` remains unchanged.

A visible default branch can support its own scoped alignment without certifying
the unseen helper branch. Likewise, a visible strict length check can support a
requested validation suboperation while chunk grouping and producer result types
remain unestablished. Such partial credit is not complete request fulfillment.

## Mechanical acceptance and reviewer judgments

The existing experimental declaration-schema normalizer still accepts
well-formed, cited overclaims mechanically. Explicit authored reviewer bases
identify their unsupported semantics using the existing review audit. The audit
does not infer truth from source text, classify model explanations or supply
independent gold labels. These are regression controls for the evidence
distinction, not a model-quality benchmark or a semantic production fix.

Relations, reasons and property declarations are preserved through normalization;
fixture inputs remain unchanged. Abstentions are not repaired, scored as errors
or turned into forced slices. All cards remain `context_required`, with unchanged
selection/qualification and independently unverified comparison/slice semantics.
