# Offline branch return and property comparison controls

Fourteen new authored controls capture the two semantic limits found in the
[nine-case Luna result](missing-link-triage-property-result-2026-10-05.md): a
declared return type was generalized across a pass-through branch, and a useful
command-string versus boolean comparison was withheld for lack of an existing
implementation relationship. These are reproducible offline examples for the
next experimental prompt revision, **not a model retest or production fix**.

Only a new test file and documentation are added. Prompt, schema, normalizer,
semantic-audit helper, production selection and qualification remain unchanged.
Historical cards, raw receipts and independent reviews are not repaired.

## What the controls establish

The tests cite the source of two small Python functions authored in the test file
and execute only those fixtures. No acquired repository code, generated example,
NumPy package or real Path implementation is executed. The fixtures reproduce
the relevant branch structure and return-property distinction, not either
library's complete contract or an integration with the original request.

| Control | Positive evidence | Claim that remains unsupported |
| --- | --- | --- |
| Declared scalar input and bytes output | Type annotations permit an explicitly declared interface comparison. | An annotation enforces rejection of collections or proves every actual return is bytes. |
| String encoding branch | The authored string fixture returns UTF-8 bytes. | This proves the complete mixed-collection detection or dtype policy. |
| Non-string branch | Bytes, a mixed list, dictionary, opaque object, integer and `None` return by identity; the list remains unchanged. | A universal bytes return or universal encoding behavior. |
| Grep command versus predicate | A demand explicitly requires command text/options; the authored filename predicate returns a boolean. | Prior adoption is necessary for this local contrast, or the contrast establishes a runtime ban or full-workflow rejection. |
| Genuine gaps and narrow slices | An unseen delegate remains unknown; the explicit mean suboperation still permits a bounded slice. | Pattern vocabulary establishes a command-generation slice or output alignment proves whole-task parity. |

The branch witnesses use ordinary authored values, not an object-array execution.
They disprove an unconditional return claim for that fixture. They do not measure
NumPy behavior, validate arbitrary caller representations or prove that the
candidate fulfills mixture detection. Declared output contrast and observed
branch behavior are separate properties and cannot silently replace one another.

The grep controls explicitly compare the same property dimension at the candidate
entrypoint without claiming it already implements the requested operation. Missing
acceptance/adoption context remains incomplete. A predicate is not a command
generator merely because both deal with patterns; that analogy cannot certify a
requested suboperation.

## Mechanical acceptance and independent review

Exact citations and property declarations are checked by the existing normalizer.
An unqualified return claim can still pass those checks. The controls then supply
explicit reviewer labels and reasons, informed by the authored branch witnesses,
to the existing audit. That audit checks label consistency; it does not read code
to infer semantic truth or automatically reject the claim in production.

Both supported local contrasts and explicit abstentions remain mechanically
valid. An unchanged grep abstention does not gain a quality score, false-negative
label or correct-rejection credit merely because a reviewer supplies a known
contrast. Known fixture claims remain context required, with semantic-verification
flags false and no selection/qualification changes. These assertions therefore
do not establish that Luna has stopped either error.

The separation of scoped regression examples from model-quality measurement
follows [OpenAI's evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices),
which recommends task-specific tests and human feedback. The fixture choices and
their semantic labels here are workspace-agent judgments, not official OpenAI
results, held-out gold labels or statistical accuracy measurements.
