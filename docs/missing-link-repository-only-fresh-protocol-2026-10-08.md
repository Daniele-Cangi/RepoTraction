## Frozen pipeline and limits

Use the production implementation at reviewed main `42807d7`, analysis contract
25, unchanged production provider instructions, schemas, normalizers, source
sampling, query generation, selection and qualification. The experimental
evidence-strength prompt is not promoted or silently substituted. This cohort
evaluates that pipeline's usefulness, not the effect of the experimental prompt.

Run at most one initial `Service` Discover investigation per frozen source, in
order, with `action=discover`, `use_ai=true`, `max_candidates=3`, `max_requests=80`,
empty `issue_url` and empty `query`. Keep the 24-file source-acquisition limit,
three generated queries and existing two-page/20-item retrieval bounds. Retain
all source coverage and retrieval limitations. Lexical retrieval is only a way
to obtain candidates; a lead still needs a demonstrated mechanism and demand.

Use `gpt-6-luna`, Responses streaming, strict JSON Schema, medium reasoning,
`store=false`, 6,000 maximum output tokens, 180,000 maximum request bytes, eight
calls per investigation and USD0.20 conservative reservation per investigation.
At the unchanged configured USD0.10 input / USD0.50 output per million tokens,
the maximum-byte reservation formula gives USD0.0212048 per call and
USD0.1696384 for eight maximum-size calls. These are local reservation bounds,
not provider invoices, promised billed prices or predicted usefulness.

The four-investigation segment is capped at **USD0.80**, within the existing
`missing-link-verification-2026-09-30` allowance and its configured **USD10 total**.
The current baseline is **529 reservations / USD7.6904081**; the frozen cumulative
segment ceiling is **USD8.4904081**, leaving USD1.5095919 conservative headroom
even if the segment reaches its cap. Native usage, including cache-read/write
and reasoning details, must be retained separately from these reservations.
Do not increase the total, reset/refund counters or create a new allowance.
These settings are proposed for the separate owned evaluator; `.env` and the
running application configuration have not been changed by this preparation.

## Required owned evaluator before execution

This document and metadata freeze alone do not make an executable cohort ready.
A separate evaluator must be implemented, checked offline, narrowly reviewed by
Codex, pass CI and merge before binding a one-shot successor to reviewed main.
It must preserve the four names/order/revisions and this protocol. Its remaining
work is caller-owned acquisition, persistence and spending safety, not a parser,
UI, semantic-scoring or production-prompt change.

The evaluator must use `Service` on private evaluation storage so original jobs,
matches, source history and account data remain unchanged. AI reservations must
still go to the **original database and original allowance**, through its atomic
`Store.reserve_ai_allowance` with the tighter USD8.4904081 ceiling. Copying data
for evaluation must never create an independent spend ledger or charge only a
copied allowance. The shared original worker lease and the evaluation service's
own lease must prevent overlapping investigations. This is audit storage, not
execution isolation for acquired code.

The unmodified Service normally passes the provider's total ceiling to Store;
therefore a caller-owned atomic reservation binding is required. A check after a
charge is insufficient. Source acquisition normally resolves the default branch;
the caller must bind that source commit read to the frozen SHA and verify the
returned commit/tree/source identity before the first paid call. It may route
the source commit endpoint to the exact pinned commit without choosing files or
mechanisms. Target retrieval remains the existing bounded live Discover flow.

Preserve all production prompt/schema bodies while privately retaining complete
decoded native terminal events before output interpretation. The receipt transport
may be delegated by the owned provider's `complete` method; downstream production
validation remains unchanged. Freeze that adapter's code/configuration, lease,
marker, terminal and atomic-cap behavior and exercise it with mocked transport
before payment. No credential, private target or generated code enters a public
report, and acquired code is never imported or executed on host Python.

Before start and before each model attempt, require provider readiness, fresh
GitHub identity, reviewed-main ancestry, all executable/source/configuration
fingerprints, immutable historical artifacts and the exact owned reservation
prefix. Use an exclusive cohort marker and one slot/job identity per ordered
investigation. No operator retry, resume, candidate replacement, enlarged caps,
query tuning, model fallback, repaired response or follow-up paid investigation
is permitted within this cohort.

The existing pipeline's candidate-local validation failures remain retained,
charged failures and may continue only as its reviewed behavior permits; they
are not sound semantic rejections or successful comparisons. Transport, identity,
refusal/incomplete terminal, persistence, fingerprint, cap or integrity errors
stop the cohort before another source. Record the interrupted slot and remaining
unattempted slots without replacing them or treating them as empty results.
The Service catches `CandidateValidationError` broadly; the owned receipt adapter
must not let a fatal native terminal or generic malformed-output error become
candidate-local continuation. An attempt latch and offline transport tests must
prove that no subsequent model call occurs after such a failure, including within
the same investigation. This distinction must be reviewed before execution.

Audit the original database with a current 529-row baseline: allow only the
owned original-allowance reservations and their exact balance increment. Keep
every prior reservation, unrelated allowance, original non-accounting table and
protected artifact unchanged. Retain evaluation jobs, full retrieval pools,
generated queries, selected/skipped candidates, raw outputs, native usage,
source/target revisions and failures privately for independent replay.

## Assessment after the initial cohort

Read every selected comparison and each abstention/rejection against only the
source and demand evidence actually supplied. Inspect query/selection omissions
and the retained pool separately; inspecting after the run must not add a paid
candidate to the initial cohort. Report acquisition, extraction, comparison and
qualification failures at their actual stage.

A useful external lead needs a current actionable request, a bounded demonstrated
contribution of the source mechanism, grounded mandatory constraints, explicit
integration gaps and target-source/prior-reference checks. Distinguish documented
contracts from actual delegate behavior, visible branches from conditionally
possible outcomes, and support for part of a request from whole-task acceptance.
Unknown prior use or novelty remains unknown. An absent detected package reference
does not establish novelty; an issue being open does not alone establish adoption.

Report useful bounded mechanisms, supported external leads, unsupported positive
labels, unsupported unknown reasons, sound wrong-candidate contrasts, candidate
validation failures, stale/non-demand targets and genuine evidence gaps separately.
Count pipeline labels separately from operator source judgments. Do not infer
accuracy from schema acceptance, greater abstention, four purposively selected
sources or selected-only history. Zero supported leads is a valid outcome; no
winner or integration proof is forced.

Only a useful source-grounded lead can motivate a later separately scoped candidate
execution/integration experiment. Isolation, a friendlier UI, site key entry and
production promotion remain gated. This preparation performs no additional model
call, reservation, source execution, production job or UI change.
