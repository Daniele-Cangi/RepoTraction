# Missing Link contract-20 corrections — 2 October 2026

These corrections follow the [incomplete contract-19 live cohort](missing-link-live-discovery-contract19-2026-10-02.md).
They are separate from that frozen experiment. No new model call, allowance reset,
historical-result migration or acquired-code execution is part of this work.

## Final transport packing

Provider context preparation now measures the same serialized body that `complete`
sends: instructions, interpreted request, source/coverage data, scoped schema,
API framing, streaming/reasoning options and JSON escaping. If it does not fit,
up to eight strictly decreasing **local packing passes** rebuild excerpts and
their citation/schema scopes. These are not HTTP retries or AI attempts.

The interpreted request is never truncated. Implementation-first selection,
source-role rules, primary API ranking, scoped IDs and explicit omissions remain.
Missing implementation or an unsatisfiable fixed payload fails before reservation
and HTTP. The final `complete` byte check also remains as a fail-closed guard.

Read-only replay of Zod's actual failed Rosetta comparison now fits at **178,554
bytes under 180,000**, with all 27 requirements unchanged and implementation
context present. Its 197 omitted source chunks remain reported. This demonstrates
transport feasibility, not a valid or useful future model judgment.

## Fair discussion citations

Citation selection keeps at most three opening root spans, then interleaves spans
from supplied discussion sources. A short root request remains available; a long
generated report cannot consume the full budget before later human comments are
considered. Original source offsets still determine citation IDs. Synthetic
omission seams and unseen text never become quotes. Duplicate visible excerpts
retain one ID. Byte/ID limits and exact-text validation remain unchanged.

Coverage records total omitted visible spans and bounded IDs/counts for sources
that received no spans. Partial coverage still prevents a complete-discussion
claim. This is deterministic coverage sharing, not semantic demand ranking.

The retained Babel/QuantEcon case now offers **10 spans from `q1`**, its feedback
request, plus two each from `q2`/`q3` and 133 from the root. Previously all 153
offered spans belonged to the root and none to `q1`. Current selection has 147
spans and explicitly reports 137 omitted visible spans. Discussion remains
incomplete; no fabricated non-demand or request interpretation is accepted.

## Candidate-owned partial contribution review

Contract **20** adds a closed `partial_support` array to each wire match. Every
proposed `partial_behavior` requires a review for its requirement ID containing:

- `basis`: `candidate_implementation`, `target_context`, `analogy` or `not_established`;
- `operation`: the concretely reusable operation;
- `requirement_part`: the specific requested suboperation it implements;
- `remaining_work`: wiring/policy/new implementation that is still required;
- `source_ids`: candidate implementation anchors also cited by that check.

Only `candidate_implementation` with all three nonempty explanations and exclusively
check-bound candidate implementation anchors can retain partial credit. Target
files, discussion, documentation, tests, types, unrelated check citations, passive
scope and missing attribution cannot satisfy that gate. Known review citations,
shape, bounds, requirement IDs and uniqueness are validated for imports too.
Reviews are retained inside normalized checks for audit/export, including an
explicit rejected target/analogy interpretation.

The comparison prompt distinguishes target-side Jest/ESLint/TypeScript/CI files
from candidate global configuration, runtime caching analogy from static AST
diagnostics, and invalid-option guards from invalid-size behavior/project tests.
Analogy/target/not-established proposals normalize to `not_demonstrated`; genuine
partial operations stay `undetermined`, never full satisfaction or automatic
execution/lead qualification. Fully supported behavior and hard conflicts retain
their independent gates.

**This is attribution/provenance validation, not automatic semantic proof.** A model
can still make a wrong claim about relevance. Named operation/request-part/new-work
fields make that claim explicit and auditable; offline fixtures cannot establish
that Luna's future answers improve. Fresh live validation remains pending.

New imports lacking the partial review cannot retain ambiguous partial labels.
Existing stored contract-19 and older analyses are not rewritten or reinterpreted
in place. Contract identity changes normally mark those results historical.

match citing another capability's `other.py` implementation retained partial
credit, including whole-file, line-span and `c1:0` aliases. It did not become an
eligible lead, but its partial attribution was incorrect.

to the **selected capability's structural evidence or definition paths**, as well

implementation definition remain accepted. Other compatibility gates are unchanged.

for separate operations sharing one file. The wire shape and budget limits are
unchanged. Contract **21** produces distinct new result identities and uses the
existing historical-result mechanism; stored contract-20 results are not rewritten
