## Reading boundaries and labels

`explicit_change_or_help_request` means visible root prose asks for a change,
implementation or concrete design/help decision. It does not mean the work is
still open, unimplemented, novel or appropriate for the source. No negative
demand label is assigned from an unread region. `insufficient_root` retains that
uncertainty; the reference-only category was available but unused in this sample.

`requested_operation` means the requested behavior itself includes the searched
operation. `context_only` means retrieving vocabulary describes implementation
context, a broader task or a different operation. This distinction uses the root
and saved query, not a new source compatibility analysis. An operation-level hit
may still impose constraints that an actual source cannot satisfy.

Twenty roots were fully read. Transmissionlines, Sigma and the memory-model article
were read at characters 0:10000 and their last 2000 characters, with the middle
explicitly unassessed. Slime's demand prose was read up to its executable CPU
reproduction; that long reproduction is not treated as independently verified
or fully read. Positive demand anchors lie in the read ranges. The article's
unread middle prevents a categorical absence claim.

All cases retain unknown current actionability, full discussion, source fit,
novelty and adoption. Comments, linked issues/PRs and target implementation were
not newly acquired. Reproduction commands, instructions and reported executions
inside issue bodies are source material only; none was executed or followed.

## What this changes in the next-step decision

An educational title is not a reliable exclusion rule: case 1 has a concrete
implementation task, unlike the answered homework in the closed selected cohort.
Similarly, broad epics contain demand without establishing a small reusable seam.
The 23 visible requests therefore do not imply 23 actionable opportunities.

Query vocabulary often lands in the wrong layer: tensor cache coherence versus
HTTP response caching, normalization as a field name versus a normalization
operation, RDF inversion versus inverse mapping iteration. The operator sample
supports testing this distinction offline; it does not validate an automatic
triage or show that rewriting queries will produce a lead.

The three operation-level roots also illustrate remaining gates. Viperstrike
already suggests using its validated parser. Firecrawl's path-prefix requirement
resembles the previously selected httpr case and proves no new source capability.
ORESoftware requires a codec/negotiation/generation contract beyond mere presence
of a MessagePack serialization call. None is declared compatible or qualified.

Before further spending, specify a separate offline demand-to-operation control
set that records the requested change, input/output shape, runtime, acceptance
constraints, exact root anchor and unknown context. Include the educational
request, async-generator flattening, tensor cache, RDF inversion and an
operation-level hit as contrast controls. Freeze labels before testing any new
policy; retained cases are development controls, never a fresh quality benchmark.
Do not require every field to be known or turn context-only labels into automatic
compatibility rejections. Any later live comparison needs a separate fresh frozen
protocol and the original cumulative allowance; this audit authorizes no payment.
